# PRD：律师本地 Word 匿名化与还原小工具

版本：v0.1 MVP  
目标平台：Windows 10 / Windows 11  
目标用户：非技术律师、律师助理、法务  
产品形态：本地桌面小程序 + 文件夹监听  
核心原则：本地运行、傻瓜式使用、宁可多打码、不允许疑似残留文件进入可上传文件夹

---

## 1. 产品背景

律师在使用外部 AI 工具处理客户 Word 文件前，需要先把文件中的客户姓名、公司名、地址、联系人、律师姓名、项目名、交易简称等敏感信息本地替换为占位符。AI 处理完成后，律师再把 AI 输出放回本地，由程序根据本地映射表恢复原始实体。

本产品不是面向技术人员的复杂平台，而是律师电脑上的小工具。MVP 不依赖本地大模型，不调用外部 API，不上传原文。系统主要依靠 Word 全结构扫描、确定性规则、高召回专有名词发现、别名归并、本地记忆和 fail-closed 门禁降低漏脱敏风险。

---

## 2. 产品目标

### 2.1 核心目标

1. 律师双击打开程序后，只需要把 `.docx` 文件放入 `01-待匿名化` 文件夹。
2. 程序自动在本地生成匿名化 Word 文件。
3. 只有通过门禁的文件才能进入 `02-已匿名化-可上传AI`。
4. 未通过门禁或存在不确定风险的文件进入 `02-需要复核-暂勿上传`。
5. 程序在本地保存加密映射表。
6. AI 返回结果放入 `03-AI结果放这里` 后，程序自动还原到 `04-已还原`。
7. 保持 Word 原始格式、段落、表格、页眉页脚、字体和基础结构。

### 2.2 安全目标

1. 原始客户文件不上传网络。
2. 映射表不明文暴露。
3. 发现不能确认安全的结构、图片、嵌入对象、残留实体时，默认拦截。
4. 匿名化后的文件中不应残留已识别实体的原文 surface form。
5. 文件名和 Word 元数据也要清理。

### 2.3 使用体验目标

1. 律师不需要理解 NER、正则、实体图谱、映射表等技术概念。
2. 主界面只显示：运行状态、处理结果、风险提示、打开文件夹、重新扫描、还原按钮。
3. 判断逻辑简单：
   - 绿色文件夹：可以上传 AI。
   - 红色文件夹：不要上传，需要复核。
4. 每个拦截文件自动生成非技术语言的风险报告。

---

## 3. 非目标 / 暂不做

MVP 不做以下内容：

1. 不接入云端大模型。
2. 不要求安装本地 LLM。
3. 不做 OCR。
4. 不支持 `.doc` 老格式。
5. 不支持 PDF。
6. 不支持 Excel、PowerPoint。
7. 不做多人协同、云端同步、SaaS 管理后台。
8. 不承诺数学意义上的绝对匿名化。
9. 不让律师逐条确认每个实体。
10. 不实现复杂模型训练。

后续版本可以增加：OCR、本地小模型、PDF、集中部署、律所级策略管理。

## 4. 产品定位

产品名称暂定：`Legal Local Anonymizer`，中文可叫 `律师本地脱敏助手`。

一句话定位：

> 一个给律师使用的 Windows 本地 Word 脱敏小工具，把客户文件在本机替换成可还原的匿名占位符，并且只有通过本地风险门禁的文件才允许上传 AI。

## 6. 文件夹结构

程序首次启动时，在用户选择的工作目录下创建：

```text
LegalAnonWorkspace/
  01-待匿名化/
  02-已匿名化-可上传AI/
  02-需要复核-暂勿上传/
  03-AI结果放这里/
  04-已还原/
  99-本地映射表-不要上传/
  logs/
  config/
```

### 6.1 文件夹说明

`01-待匿名化`  
律师放入原始 `.docx` 文件。

`02-已匿名化-可上传AI`  
只放置通过门禁的匿名化文件。律师可以上传这里的文件给 AI。

`02-需要复核-暂勿上传`  
放置未通过门禁或存在不确定风险的匿名化文件、风险报告、高亮复核版。

`03-AI结果放这里`  
律师把 AI 处理后的 `.docx` / `.txt` / `.md` 文件放入这里。

`04-已还原`  
程序输出已恢复原文实体的文件。

`99-本地映射表-不要上传`  
保存加密映射表和本地案件记忆。律师不应上传该文件夹中的任何内容。

## 7. 核心流程

### 7.1 匿名化流程

```text
原始 .docx
  -> 文件稳定性检查
  -> Word 全结构文本抽取
  -> 候选实体发现
  -> 别名 / 简称 / 定义词归并
  -> 生成本地映射表
  -> 占位符替换
  -> 文件名与元数据清理
  -> 残留扫描
  -> 风险门禁
      -> 通过：输出到 02-已匿名化-可上传AI
      -> 不通过：输出到 02-需要复核-暂勿上传
```

### 7.2 还原流程

```text
AI 输出文件
  -> 扫描占位符
  -> 查找对应映射表
  -> 校验占位符
  -> 替换回原始文本
  -> 输出到 04-已还原
```

## 8. MVP 功能需求

### FR-01：启动与工作区初始化

程序启动后：

1. 检查是否已设置工作区。
2. 若没有工作区，提示用户选择或创建工作区。
3. 自动创建标准文件夹。
4. 显示运行状态。
5. 启动文件夹监听。

验收标准：

- 首次启动后，用户能看到完整文件夹结构。
- 关闭重开后，程序记住上次工作区。

---

### FR-02：文件夹监听与重新扫描

程序监听：

```text
01-待匿名化
03-AI结果放这里
```

要求：

1. 新文件进入后自动处理。
2. 文件复制未完成时不能立即读取，应等待文件稳定。
3. 支持手动点击“重新扫描”。
4. 已处理文件不重复处理，除非文件内容或修改时间变化。

验收标准：

- 拖入 `.docx` 后自动处理。
- 点击“重新扫描”可以处理之前漏掉的文件。

---

### FR-03：Word 全结构文本抽取

MVP 必须扫描以下 Word 文本区域：

1. 正文段落。
2. 表格。
3. 页眉。
4. 页脚。
5. 脚注。
6. 尾注。
7. 批注。
8. 文本框中的可读取文本。
9. 超链接显示文本。
10. Word 核心属性、扩展属性和自定义属性中的文本字段。

如果发现以下不支持结构，应进入复核，不得放行：

1. 图片。
2. OLE 嵌入对象。
3. 加密或受保护文档。
4. 无法解析的 XML part。
5. 修订痕迹中含有删除文本但无法安全处理。

验收标准：

- 页眉页脚中的公司名也能被替换或触发复核。
- 表格中的联系人、地址、公司名能被替换。
- 有图片或嵌入对象时，不进入可上传文件夹。

---

### FR-04：候选实体发现

MVP 使用确定性规则与高召回候选发现，不依赖本地大模型。

必须发现以下类型：

```text
PERSON           人名 / 律师 / 董事 / 联系人 / 签署人
ORG              公司 / 律所 / 机构 / 银行 / 集团
ORG_ALIAS        公司简称 / 缩写 / 定义词
ADDRESS          地址 / 签署地 / 办公地点
EMAIL            邮箱
PHONE            电话 / 手机 / 传真
ID_NUMBER        身份证 / 护照 / 证件号
REG_NUMBER       统一社会信用代码 / 注册号 / 税号
BANK_ACCOUNT     银行账号
URL_DOMAIN       网址 / 域名
MATTER           案件名 / 项目名 / 交易名 / 协议标题中的专有名词
UNKNOWN_PROPER   高风险区域中的未知专有名词
DOC_META         文件名或元数据中的敏感信息
```

候选来源包括：

1. 固定格式正则：邮箱、电话、证件号、统一社会信用代码、网址、银行账号等。
2. 公司后缀规则：`Co., Ltd.`, `Limited`, `LLC`, `LLP`, `Inc.`, `Corporation`, `Pte`, `GmbH`, `AG`, `B.V.`, `S.A.`, `Pty`, `有限公司`, `集团`, `合伙企业`, `律师事务所` 等。
3. 地址上下文规则：`Address`, `Registered Office`, `住所`, `地址`, `签署地`, `联系地址`, `Level`, `Floor`, `Room`, `Road`, `Street`, `Building`, `District`, `Province` 等。
4. 法律上下文区域：`TO`, `FROM`, `CC`, `ATTENTION`, `RE`, `SUBJECT`, `甲方`, `乙方`, `丙方`, `签署`, `授权代表`, `董事`, `联系人`, `律师`, `Party A`, `Party B`, `Client`, `Counsel`, `Director` 等。
5. 定义词与简称规则：括号、引号、`hereinafter`, `referred to as`, `简称`, `以下简称` 等模式。
6. 全大写缩写规则：2-8 个字符的英文大写缩写，排除白名单中的通用法律词。
7. 英文专有名词规则：连续 Title Case 词组，尤其出现在标题、收件人、主题、定义、签名、表格标签旁。
8. 中文姓名候选：在 `姓名`, `联系人`, `董事`, `律师`, `签字`, `授权代表`, `甲方代表`, `乙方代表` 等上下文附近出现的 2-4 个中文字符。
9. 文件名与 Word 元数据扫描。
10. 本地案件记忆匹配。

验收标准：

- 能识别 `Rockit Trading (Shanghai) Co., Ltd. ("RGL")` 中的公司全称和 `RGL`。
- 能识别 TO / FROM / RE 中的人名、公司名、项目名和缩写。
- 能识别中英文地址块。
- 能识别甲方、乙方、签署地、联系人、授权代表附近的实体。

---

### FR-05：实体归并与别名表

系统应将同一主体的不同写法合并为一个 canonical entity。

示例：

```text
Rockit Trading (Shanghai) Co., Ltd.
Rockit Trading
RGL
RTC
```

可归并为：

```text
ORG_001
```

但还原时必须保持原始表面写法，因此映射表应按 surface form 保存。

示例：

```text
[[ORG_001_FULL_A7F]]  -> Rockit Trading (Shanghai) Co., Ltd.
[[ORG_001_ALIAS_B2K]] -> RGL
[[ORG_001_SHORT_C3M]] -> Rockit Trading
```

验收标准：

- 同一文档中相同原文字符串应使用同一个 placeholder。
- 定义词中的别名应自动加入映射。
- 还原后应恢复为 AI 输出中 placeholder 对应的原始 surface form。

---

### FR-06：占位符生成

占位符格式：

```text
[[TYPE_三位编号_角色_校验码]]
```

示例：

```text
[[ORG_001_FULL_A7F]]
[[ORG_001_ALIAS_B2K]]
[[PERSON_001_FULL_M9Q]]
[[ADDRESS_001_FULL_D8X]]
[[MATTER_001_FULL_Q4R]]
[[UNKNOWN_001_PROPER_Z2P]]
```

要求：

1. 占位符可读，保留实体类型。
2. 占位符足够稳定，便于 AI 保持。
3. 校验码用于防止误还原。
4. 同一原文 surface form 在同一案件中应尽量复用同一占位符。

---

### FR-07：匿名化 Word 生成

要求：

1. 基于原 `.docx` 复制生成，不重新排版。
2. 在 OpenXML 文本节点中做原位替换。
3. 尽量保留字体、段落、表格、页眉页脚、脚注、批注。
4. 替换实体跨多个 run 时，应正确合并或清空相关文本节点。
5. 清理 Word 元数据中的作者、标题、公司、主题等字段。
6. 输出文件名也必须匿名化，不能包含原始客户名或项目名。

输出文件名示例：

```text
原：Rockit Trading Share Purchase Agreement.docx
匿名：匿名化_20260516_142233_001.docx
```

验收标准：

- 匿名文件能用 Word 打开。
- 表格和页眉页脚格式不明显破坏。
- 原文件名中的敏感词不会出现在输出文件名中。

---

### FR-08：残留扫描

匿名化完成后必须进行残留扫描。

扫描内容：

1. 匿名化 `.docx` 内所有文本节点。
2. 匿名化文件名。
3. Word 元数据。
4. 风险报告中不得包含原始敏感文本，除非位于本地复核报告并明确标注不要上传。MVP 建议风险报告只写类型和位置，不写完整原文。

扫描方式：

1. 原实体 surface form 精确扫描。
2. 大小写归一扫描。
3. 空格、标点、全角半角归一扫描。
4. 对简称和全大写缩写重新扫描。
5. 对高风险区域重新运行候选实体发现。

验收标准：

- 如果页眉仍残留 `RGL`，文件必须进入 `02-需要复核-暂勿上传`。
- 如果 metadata author 仍为真实姓名，文件必须进入复核。

---

### FR-09：风险门禁

只有满足以下条件的文件才能进入 `02-已匿名化-可上传AI`：

1. 支持的 Word 文本区域全部扫描成功。
2. 未发现图片、OLE 或其他不支持结构。
3. 所有已识别原始实体 surface form 均无残留。
4. 匿名文件重新扫描未发现高风险未知专有名词。
5. 文件名和元数据已清理。
6. 映射表已成功加密保存。
7. 占位符格式完整。

任一条件失败，进入 `02-需要复核-暂勿上传`。

风险报告应包括：

```text
处理结果：暂勿上传
原因：
1. 页眉区域发现疑似未处理缩写。
2. 文档包含图片，系统无法确认图片中是否有客户信息。
3. 文档属性 Author 字段包含疑似真实姓名，已清理但建议复核。
建议：请人工复核该文件，不要直接上传 AI。
```

---

### FR-10：本地映射表

映射表必须保存在：

```text
99-本地映射表-不要上传/
```

MVP 使用加密 JSON 文件，不上数据库。

文件格式：

```text
{jobId}.mapping.json.enc
{jobId}.summary.txt
case_memory.enc
```

`summary.txt` 不包含原文实体，只包含统计信息：

```text
文件：匿名化_20260516_142233_001.docx
公司/组织：5
人名：8
地址：3
邮箱/电话：6
项目/交易名：2
未知专有名词：4
门禁结果：通过
```

映射表内容加密前逻辑结构：

```json
{
  "jobId": "20260516-142233-001",
  "sourceFileHash": "...",
  "createdAt": "2026-05-16T14:22:33",
  "entries": [
    {
      "placeholder": "[[ORG_001_FULL_A7F]]",
      "original": "Rockit Trading (Shanghai) Co., Ltd.",
      "entityType": "ORG",
      "entityId": "ORG_001",
      "surfaceRole": "FULL"
    }
  ]
}
```

---

### FR-11：AI 输出还原

用户把 AI 输出放入：

```text
03-AI结果放这里
```

支持格式：

```text
.docx
.txt
.md
```

还原要求：

1. 自动扫描 placeholder。
2. 根据 placeholder 找到映射表。
3. 替换为原始文本。
4. 输出到 `04-已还原`。
5. 如果发现未知 placeholder，生成 warning report。
6. 如果 placeholder 被 AI 改坏，尽量做轻度容错，但不能错误还原。

验收标准：

- AI 输出中的 `[[ORG_001_FULL_A7F]]` 能恢复为原公司名。
- 如果 AI 删除或破坏占位符，系统能提示风险。

---

### FR-12：上传 AI 提示词文件

每个通过门禁的匿名文件旁边生成：

```text
上传AI提示词.txt
```

内容：

```text
请处理随附文件。请勿修改、翻译、拆分、删除任何形如 [[ORG_001_FULL_A7F]] 的占位符。
请在你的输出中保持这些占位符原样，以便我在本地恢复原始信息。
```

## 9. 用户界面需求

主界面包含：

1. 当前工作区路径。
2. 状态：运行中 / 暂停 / 处理中 / 出错。

## 11. 成功指标

MVP 成功指标：

1. 对测试集中的已标注敏感 surface forms，匿名化后残留数量为 0。
2. 支持正文、表格、页眉、页脚、脚注、批注中的替换。
3. 含图片或嵌入对象的文件不会误放行。
4. AI 输出还原准确率接近 100%。
5. 普通律师无需配置即可完成基本流程。
6. 错误文件不会静默失败，必须进入复核或错误报告。

## 12. 测试样例要求

至少准备以下测试文件：

1. 英文 memo：TO / FROM / RE 中含人名、公司名、简称、项目名。
2. 英文合同：公司全称 + 括号简称 + 地址 + 签名栏。
3. 中文合同：甲方、乙方、签署地、联系人、统一社会信用代码。
4. 带页眉页脚的 Word：页眉含公司简称。
5. 带表格的 Word：表格里有人名、地址、电话。
6. 带批注的 Word：批注中含律师姓名。
7. 带图片的 Word：应进入复核。
8. AI 输出 txt：含 placeholder，应能还原。
9. AI 输出 docx：placeholder 跨 run，也应尽量还原。
